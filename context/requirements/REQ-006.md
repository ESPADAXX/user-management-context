## Rule
WHEN a user account, role, status or invitation changes, THE SYSTEM SHALL record who did it, what changed, on which user, and when.
THE SYSTEM SHALL let only admins read the audit log, newest first, and SHALL never update or delete an audit event.

## Acceptance criteria
- Creating a user, changing a role, inviting and deactivating → one audit event each, with actor, action, target and time
- Admin reads the log → 200, newest first
- Manager or member → 403
- The API has no endpoint that updates or deletes an audit event
