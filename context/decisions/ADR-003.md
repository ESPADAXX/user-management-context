## Context
Every developer would otherwise invent an error shape, and the web app and contract tests need one.

## Decision
Every error response has `Content-Type: application/problem+json` and the body
`{ "type": "about:blank", "title": "...", "status": 409, "detail": "...", "errors": [...] }`.
Validation errors (422) list each field in `errors`.

## Alternatives rejected
- `{ "error": "..." }`: no standard, no field list.

## Consequences
The contract defines one `Problem` schema reused by every 4xx response.
